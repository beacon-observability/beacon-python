# Beacon Python 1.2.2

Status: published on 2026-10-28. Both packages and the [GitHub Release](https://github.com/beacon-observability/beacon-python/releases/tag/v1.2.2) passed [public-artifact acceptance](../validation/1.2.2.md).

## Changes

- Adopt OpenTelemetry Contrib `v0.66b1` (`a22d03307b27d958ca9dc340a3514ae1898f63e7`) and its paired Core `v1.45.1` (`14971cef9c84c2354cbaf6871090896fad0f9a1a`) from [synchronization PR #63](https://github.com/beacon-observability/beacon-python/pull/63).
- Release matching `beacon-otel` and `beacon-profiling` packages at `1.2.2`, including the exact profiling-extra dependency.
- Preserve Beacon Security, Profiling, command entry points, and opt-in defaults across the upstream synchronization.
- Exercise the ASGI receive-cancellation regression with both asyncio and Trio in CI and release validation.

Upstream release details: [Contrib v0.66b1](https://github.com/open-telemetry/opentelemetry-python-contrib/releases/tag/v0.66b1) and [Core v1.45.1](https://github.com/open-telemetry/opentelemetry-python/releases/tag/v1.45.1). The full source pins remain in [upstream.lock.json](../upstream.lock.json).

## Compatibility and Limits

Security remains embedded in `beacon-otel`, disabled by default, and bound to the existing schema and fingerprint version 1 contract. Standard-GIL CPython 3.11–3.14 supports its runtime; CPython 3.10 receives package and schema checks. Profiling package tests cover CPython 3.10–3.14. Gunicorn requires `preload_app=False`.

This upstream upgrade does not establish new production DataKit, Collector, throughput, or overhead acceptance. Existing operational limits from [1.2.1](1.2.1.md) still apply. Candidate tests and public release acceptance are separate requirements.

## Publication and Verification

Follow [RELEASING.md](../RELEASING.md): pass candidate wheel and sdist checks and the five-runtime CI, complete application/backend acceptance, tag the verified commit as `v1.2.2`, and manually run `Publish Beacon Python` with the release gate enabled. Publish Profiling first, then the main package, using the protected PyPI environments. Restore the release gate afterward.

After publication, verify GitHub and PyPI artifact SHA-256 digests and install `beacon-otel[profiling,requests]==1.2.2` in a clean environment. Verify the CLI, auto-instrumentation, Security default-off behavior and enabled finding/runtime-SBOM delivery, and the target backend. Record the exact commit, workflow run, artifact digests, runtime, and backend results before claiming public acceptance.

To roll back, install `beacon-otel[profiling,requests]==1.2.1` in a clean environment and validate the application. Previously published versions and tags remain immutable.
