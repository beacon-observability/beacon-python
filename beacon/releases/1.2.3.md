# Beacon Python 1.2.3

Status: release candidate, pending publication and public-artifact acceptance.

## Changes

- Align Python Security telemetry with the shared schema v2 contract and the Beacon Java simplification in [PR #66](https://github.com/beacon-observability/beacon-python/pull/66). The Security fingerprint remains v1.
- Emit only `beacon.security.finding` and `beacon.security.sbom.inventory` through OTel Logs. Inventory is published after every successful collection, including unchanged and empty lists; failed collections leave the prior valid inventory intact.
- Compact finding payloads, retain evidence sampling and actual coverage signals, and match local finding exceptions by stable `finding_id` across process restarts.
- Keep Security opt-in and embedded in `beacon-otel`. Publish matching `beacon-otel` and `beacon-profiling` packages at `1.2.3` with the existing Contrib `v0.66b1` / Core `v1.45.1` baseline.

## Compatibility and Migration

Security event schema v2 is incompatible with v1 consumers. Consumers must accept the compact finding shape, `occurrence_id`, direct component metadata, successful empty inventories, and complete inventory parts grouped by `instance_id + observed_at`. Removed health, summary, and export diagnostic events are no longer emitted. Existing stored v1 events retain their historical meaning.

Security supports standard-GIL CPython 3.11–3.14; CPython 3.10 receives package and schema checks. Profiling package checks cover CPython 3.10–3.14. Gunicorn requires `preload_app=False`. Bounded collection, sampling, delivery, and backend limitations remain documented in the [Security usage guide](../../beacon-otel/README.md).

## Publication and Verification

Follow [RELEASING.md](../RELEASING.md): verify candidate wheels and sdists, the five-runtime CI, and application/backend acceptance before tagging `v1.2.3`. Manually run the protected publication workflow with the temporary release gate enabled. Publish Profiling first, then `beacon-otel`, and restore the gate afterward.

After publication, verify PyPI and GitHub artifact hashes, clean-environment installation, the CLI, Security default-off behavior, and enabled finding plus runtime-SBOM delivery. Record exact provenance and results before claiming public-artifact acceptance.

To roll back, install `beacon-otel[profiling,requests]==1.2.2` in a clean environment and validate the application. Published artifacts and tags remain immutable.
