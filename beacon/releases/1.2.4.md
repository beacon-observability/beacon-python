# Beacon Python 1.2.4

Security findings classified as `attack_evidence.status=no_evidence` are no longer
exported by default. Set `BEACON_SECURITY_EXPORT_NO_EVIDENCE_ENABLED=true` to restore
the previous behavior. `unknown` and `suspected` remain eligible, and SBOM inventory
export is unchanged. Filtering precedes queue admission and does not count as loss.
Internal detection, local finding snapshots, span summaries, and same-request
evidence upgrades remain available. This setting controls event export, not a
safety verdict or whether a modeled flow exists.

Both `beacon-otel` and `beacon-profiling` use version 1.2.4. The adopted OTel baseline
remains Contrib 0.66b1 / Core 1.45.1. Security retains schema v2 and fingerprint v1;
its runtime support remains CPython 3.11–3.14. The complete external DataKit and
backend compatibility matrices are not implied by automated receiver tests.

Rollback: pin `beacon-otel[profiling]` to 1.2.3. To keep the new build and restore
ordinary finding exports, enable the configuration switch above.
