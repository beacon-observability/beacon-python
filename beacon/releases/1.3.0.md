# Beacon Python 1.3.0

## Changes

- Security findings and dependency inventories now use the SIEM envelope as the
  only output format. The complete serialized evidence remains in `message`.
- Retain `trace_id`, `span_id`, and `instance_id` for correlation. Remove
  `server_span_id` and `current_span_id`; `span_id` identifies the span active
  at detection. Require process identity in the envelope schema.
- Add individual extras and `[all]` for 51 released instrumentation packages.
  The base installation remains minimal; profiling is a separate extra.
- Keep Contrib v0.66b2 / Core v1.45.2 and the existing multipart profiling
  uploader selected with `OTEL_PROFILING_EXPORTER=http`.

## Upgrade and rollback

Install matching `beacon-otel` and `beacon-profiling` version 1.3.0 packages.
Consumers must read the SIEM envelope and parse `message` for detailed evidence
and inventory assembly. There is no legacy-output switch. Fingerprint v1 is
unchanged. Update span lookups to `span_id`. Existing stored events are unchanged.
No-evidence findings remain filtered by default; explicitly enable their export
with `BEACON_SECURITY_EXPORT_NO_EVIDENCE_ENABLED=true` if required.

Use selected extras to limit dependency constraints, for example
`pip install 'beacon-otel[fastapi,redis,pymysql]==1.3.0'`. `[all]` includes logging
and system metrics plugins and applies the combined constraints of all plugins.
Use `[all,profiling]` to include profiling. Application frameworks and database
clients remain application-managed dependencies.

Actor and client IP remain empty when trusted request enrichment is unavailable.
Finding outcome is unknown; informational severity is a log level, not assessed
risk. Profiling remains experimental. Collector acceptance does not establish
production backend acceptance. For rollback, reinstall the matching 1.2.7 package
pair and restore consumers for its original Security event shape.
