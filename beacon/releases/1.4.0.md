# Beacon Python 1.4.0

## Changes

- Adopt Security contract `d9d76e5a41d974d294bb596e06918bb954319bf6`.
  Security findings and dependency inventory now use one compact v2 JSON Body,
  without a SIEM envelope or `message` wrapper.
- Move logical `observed_at` to native OTel `time_unix_nano`, preserving available
  precision up to nine fractional digits. Invalid, unset and signed-int64
  overflowing timestamps fail export explicitly; queue flush time is never used.
- Move finding `occurrence_id` to LogRecord `attributes.event_id`. Inventory
  retains its deterministic ID per collection and part. Retain Body `source`,
  evidence, dependency structure and existing trace/span correlation fields.
- Measure Body limits and inventory partitions after the field moves; rate
  budgets also reserve native metadata and attribute bytes. Diagnostic JSONL
  retains native timestamp and attributes outside the exact Body string.
- Preserve schema version 2, fingerprint version 1, default `no_evidence` export
  filtering, the 51 instrumentation extras, and optional profiling.
- Keep Contrib v0.66b2 / Core v1.45.2. Profiling retains the multipart HTTP uploader
  selected with `OTEL_PROFILING_EXPORTER=http`.

## Upgrade and rollback

Upgrade the matching package pair to 1.4.0 if profiling is installed. For example:

```bash
pip install --upgrade 'beacon-otel[fastapi,profiling]==1.4.0'
beacon --version
```

Coordinate producer and receiver adoption. Receivers read event time from native
`time_unix_nano` and occurrence identity from LogRecord `attributes.event_id`;
parse Body once for all remaining v2 fields. Do not require Body `observed_at`,
`occurrence_id`, or `message`. Inventory assembly uses Body `instance_id`, native
event time, and Body `part_index`/`part_count`; incomplete rounds must not clear
previous completed inventory. Historical records retain their original decoder.
There is no format-selection switch.

Diagnostic evidence JSONL now has `time_unix_nano` as a decimal string, `body` as
the exact compact Body string, and `attributes` outside Body. This diagnostic
wrapper is never sent as the OTLP Body. Consumers of these files must adapt too.

Security remains opt-in on standard-GIL CPython 3.11–3.14; general zero-code
instrumentation supports Python 3.10–3.14. Missing trace context is not fabricated.
Attack-evidence statuses do not guarantee successful exploitation. Profiling
remains experimental. Local transport checks do not establish production backend
compatibility.

For rollback, reinstall matching 1.3.0 packages and restore its SIEM-envelope
receiver and diagnostic-file decoder. Do not rewrite historical stored events.
