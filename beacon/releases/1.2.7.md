# Beacon Python 1.2.7

Status: prepared for publication; this PR does not publish to PyPI or create a tag.

## Changes and migration

Restore the DataKit-compatible multipart/pprof uploader and select it with
`OTEL_PROFILING_EXPORTER=http`. Use
`OTEL_PROFILING_ENDPOINT=http://127.0.0.1:9529/profiling/v1/input` for the local
receiver. Legacy `datakit` and `pprof_http` names remain aliases, and an explicit
`OTEL_PROFILING_PPROF_UPLOAD_URL` retains precedence.

For deployments configured by 1.2.6's OTLP Profiles migration, change the exporter
to `http` and set the profiling endpoint above. The environment-selected uploader
no longer consumes `OTEL_EXPORTER_OTLP_PROFILES_*`. The `otlp` name is reserved
for future protocol support; explicitly constructed low-level OTLP exporters
remain available. The current `file` exporter API is retained.

Both `beacon-otel` and `beacon-profiling` use version 1.2.7. Sampling, bounded
buffers, profile encoding and Security behavior are unchanged by release preparation.
Contrib remains v0.66b2 and Core remains v1.45.2 at the commits recorded in
[upstream.lock.json](../upstream.lock.json).

## Validation and publication

Build and test matching wheel/sdist pairs and their metadata before publication.
Install the wheels together in a clean application and verify the CLI, profiling
configuration and receiver path. The release PR records candidate checks; the
protected publication workflow and subsequent public-artifact acceptance remain
required. Profiling is experimental, and existing runtime/backend limits apply.

To roll back, install the earlier verified package pair and its matching
configuration. Version 1.2.4 retains the compatible upload URL path; 1.2.6 uses
the OTLP Profiles configuration. Never overwrite existing PyPI artifacts.
