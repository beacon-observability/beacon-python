# Beacon Python 1.2.1

This patch release publishes matching `beacon-otel` and `beacon-profiling` packages. Security remains embedded in `beacon-otel`, opt-in and disabled by default. The Contrib `v0.65b0` / Core `v1.44.0` baseline is unchanged.

## Compatibility and Operational Limits

Security supports standard-GIL CPython 3.11–3.14. CPython 3.10 receives package and schema validation; its Security runtime remains unsupported. Profiling package tests run on CPython 3.10–3.14; handled-exception collection requires `sys.monitoring` on 3.12+. Gunicorn requires `preload_app=False`.

Collection and delivery use finite budgets. Saturated buffers and unavailable exporters can drop telemetry; delivery remains best effort. Lock profiling now samples before allocating samples or walking stacks, and suppresses its own internal locks. Tune the documented sampling and buffer settings for each workload. Full-sampling lock collection still has measurable overhead.

Attack evidence remains independent of risk classification and does not establish exploit success. Unsupported syntax and absent network/path policy remain unknown. Counters are process-local. A trace ID does not guarantee that a trace was retained.

The validated backend path uses compatible pprof and OTLP HTTP/protobuf traces and logs. OTLP Profiles dictionary and reference checks use a local protocol receiver; this release does not claim a new production DataKit or Collector qualification.

## Validation and Upgrade

See the [versioned acceptance record](../validation/1.2.1.md). The release candidate combines all 19 fixes and passed 343 local tests before version preparation. Publication additionally requires the five-version installed-wheel CI and the official protected publishing workflow.

Install `beacon-otel[profiling,requests]==1.2.1`, adding the framework extras your application uses. To roll back, install `beacon-otel[profiling,requests]==1.2.0` in a clean environment. Previously published versions and tags remain immutable.
