# Beacon Python 1.2.3 Public Release Verification

Date: 2026-10-30.

The stable `v1.2.3` tag resolves to `87d08269260113d34afbc627cd0bfcb18c1f68b4`. Matching `beacon-otel` and `beacon-profiling` distributions were published at `1.2.3`. Security remains embedded in `beacon-otel` and disabled by default.

## Source and Publication

- [Security telemetry PR #66](https://github.com/beacon-observability/beacon-python/pull/66) changes the event contract to schema v2 while retaining fingerprint v1. [Release preparation PR #67](https://github.com/beacon-observability/beacon-python/pull/67) synchronizes both package versions and release documentation.
- [Merged-source CI](https://github.com/beacon-observability/beacon-python/actions/runs/40920179292) passed installed-wheel checks on CPython 3.10–3.14. Security runtime tests ran on supported CPython 3.11–3.14; CPython 3.10 received package and schema checks.
- The [protected publication workflow](https://github.com/beacon-observability/beacon-python/actions/runs/40920840472) passed build and tests, published Profiling before the main package, and created the [GitHub Release](https://github.com/beacon-observability/beacon-python/releases/tag/v1.2.3). The temporary `BEACON_PYPI_RELEASE_ENABLED` variable was restored to `false`.

## Public Package Verification

Public PyPI JSON metadata for both versions reports the SHA-256 values below, matching the GitHub Release asset digest fields. A clean CPython 3.14.3 environment installed `beacon-otel[profiling,flask,requests]==1.2.3` from the public PyPI index. `uv pip check` found no incompatible dependencies, and `beacon --version` reported `Beacon Python 1.2.3`.

An ordinary Flask application using the installed public packages was launched through `beacon` and observed through a local OTLP HTTP/protobuf receiver:

- With Security off, one application request produced a Trace and no Security Logs.
- With Security enabled and an explicit application include prefix, one request produced nine finding events and one runtime-SBOM inventory. All ten Security events validated against schema v2, and all nine findings carried Trace and server-span IDs.
- Candidate-wheel smoke runs on CPython 3.14.3 also exercised Flask 3.1.3 and FastAPI 0.141.1 with Starlette 1.6.0. Each framework produced nine findings; all 23 combined candidate Security events validated against schema v2.

Direct download of the public archives and GitHub workflow artifacts timed out from the validation host. Therefore, this record verifies PyPI and GitHub published digest metadata and the installed package behavior, but does not claim a local byte-for-byte comparison of independently downloaded archives. The OTLP receiver establishes local protocol behavior, not new production DataKit qualification.

## Compatibility and Rollback

Security schema v2 requires consumer changes for compact findings, `occurrence_id`, and complete inventory replacement; see the [release notes](../releases/1.2.3.md). Existing bounded-delivery and coverage limits still apply. Attack evidence is not proof of exploit success.

To roll back, install `beacon-otel[profiling,flask,requests]==1.2.2` in a clean environment and validate the application. Published artifacts and tags remain immutable.
