# Beacon Python 1.2.2 Public Release Acceptance

Date: 2026-10-28.

The stable `v1.2.2` tag resolves to `f1bcf42e3c59a8ab4e6c13f25907829f9d6075cb`. Both `beacon-otel` and `beacon-profiling` were published at `1.2.2`. Security remains embedded in `beacon-otel`, opt-in and disabled by default.

## Source and Build Evidence

- [Synchronization PR #63](https://github.com/beacon-observability/beacon-python/pull/63) adopts Contrib `v0.66b1` (`a22d03307b27d958ca9dc340a3514ae1898f63e7`) and paired Core `v1.45.1` (`14971cef9c84c2354cbaf6871090896fad0f9a1a`). [Release preparation PR #64](https://github.com/beacon-observability/beacon-python/pull/64) aligns both product versions and includes Trio in CI and release validation.
- [Merged-source CI](https://github.com/beacon-observability/beacon-python/actions/runs/40628887800) passed installed-wheel checks on CPython 3.10–3.14. Security runtime checks run on supported standard-GIL CPython 3.11–3.14; CPython 3.10 receives package and schema validation.
- Local installed-wheel regression on the exact merged source passed 343 distinct tests on CPython 3.12.3, with no failures or skips: 12 package/CLI, 110 Profiling and 221 Security tests. The four schema tests were also repeated separately and are included in the Security total.
- [Official build and publication](https://github.com/beacon-observability/beacon-python/actions/runs/40629450154) succeeded. Profiling was published before the main package after separate protected-environment approvals. The temporary release variable is `false`; reviewer and tag restrictions remain active.

## Public Artifact Acceptance

Both public PyPI wheel and sdist downloads match the four official workflow artifacts and GitHub Release attachments by SHA-256. A clean CPython 3.12.3 environment installed the downloaded public wheels without a package cache or repository source imports. Direct public-index resolution stalled in the validation environment, so third-party dependencies were resolved through a package mirror; the Beacon wheel bytes came directly from public PyPI and were verified before installation. Dependency compatibility checks passed and `beacon --version` reported `Beacon Python 1.2.2`.

An ordinary Flask application with no telemetry imports was launched through the installed `beacon` command. A local HTTP/protobuf receiver decoded application traces and Security Logs; a compatible pprof endpoint decoded gzip profiles containing samples.

- Default configuration: three application requests emitted traces and non-empty profile uploads, with no active Security runtime, Security threads, Security events or local output.
- Explicitly enabled Security: three SQLite dynamic-template requests produced three finding observations with one finding ID and distinct occurrence IDs. Every finding's trace and span IDs matched an exported application span.
- Inputs `12`, `1 OR 1=1`, `14` produced `no_evidence`, `suspected`, `no_evidence` with the ANSI dialect explicitly selected.
- Runtime SBOM records and non-empty compatible pprof uploads reached the receiver. Neither phase created local Security output or `.pprof` files.
- The runtime also emitted collection-incomplete diagnostics. This acceptance does not imply complete application coverage.

The official-wheel application acceptance and the independently downloaded public-wheel acceptance both passed. The local candidate used Hatchling 1.32.4 and the official workflow used 1.33.0. The two wheel archives differ only in the `WHEEL` generator field and its `RECORD` entry; application code and dependency metadata are identical. Both source distributions match byte for byte. Release identity uses the official artifact digests below.

## Boundaries and Rollback

This is local protocol acceptance, not a new production DataKit or Collector qualification. The validated profile ingestion path uses compatible pprof; no new production OTLP Profiles claim is made. Security requires an explicit application include prefix and standard-GIL CPython 3.11–3.14. Gunicorn requires `preload_app=False`.

Existing bounded-delivery, sampling and coverage limits remain documented in the [release notes](../releases/1.2.2.md) and [1.2.1 acceptance record](1.2.1.md). Attack evidence is not proof of exploit success.

To roll back, install `beacon-otel[profiling,flask,requests]==1.2.1` in a clean environment and validate the application. Published tags and artifacts remain immutable.
