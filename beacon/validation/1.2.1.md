## Public Artifact Acceptance

A clean CPython 3.12.3 environment installed `beacon-otel[profiling,flask,requests]==1.2.1` from public PyPI with cache disabled and without repository sources. The CLI and both installed distribution versions matched `1.2.1`. The wheel and sdist files on PyPI, the official workflow and GitHub Release have matching SHA-256 digests.

An application with no telemetry imports was launched through the installed `beacon` command. A local OTLP HTTP/protobuf receiver decoded real application spans and Security Logs, and a compatible pprof endpoint decoded uploaded gzip profiles.

- Default configuration: three Flask requests emitted application spans and compatible pprof uploads, with no Security runtime or Security threads, findings, runtime-SBOM records or local output.
- Explicitly enabled Security: three requests through one native SQLite dynamic-template sink emitted findings sharing one finding ID, with three distinct occurrence IDs and counts `1, 2, 3`. Each log record's trace and span IDs matched the request's server span.
- Request fragments `12`, `1 OR 1=1`, `14` produced `no_evidence`, `suspected`, `no_evidence` with the ANSI dialect explicitly selected. Detail sampling was `true`, `true`, `false`, retaining the stronger occurrence's evidence while classifying each request independently.
- Runtime SBOM and non-empty compatible pprof uploads reached the receiver. No local Security output or `.pprof` files were created in either phase.

## Additional Candidate Validation

A local HTTP/protobuf receiver validated empty, single-sample and multi-sample OTLP Profiles dictionaries, reserved zero entries and cross references. Lock, queue and logging workloads verified pre-allocation sampling, internal suppression and bounded buffer drops. Full-sampling lock overhead remains measurable; sampling and buffer budgets must be tuned to the workload.

## Boundaries and Rollback

This is local protocol acceptance, not a new production DataKit or Collector qualification. The ingestion path validated here uses compatible pprof, not OTLP Profiles. Profiling package checks cover CPython 3.10–3.14; handled-exception sampling requires `sys.monitoring` on 3.12+. Security requires an explicit application include prefix and standard-GIL CPython 3.11–3.14. Gunicorn requires `preload_app=False`.

Telemetry collection and delivery remain bounded best effort. Unsupported syntax, imprecise evidence and absent network/path policy remain unknown; attack evidence does not establish exploit success. Counters are process-local and a trace ID does not guarantee trace retention. See the version-pinned package README and release notes for settings and supported scope.

To roll back, install `beacon-otel[profiling,flask,requests]==1.2.0` in a clean environment. Published tags and artifacts remain immutable.
