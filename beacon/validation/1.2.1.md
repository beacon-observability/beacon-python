# Beacon Python 1.2.1 Release Acceptance

## Candidate Scope

Both Beacon distributions use version `1.2.1`. Security remains opt-in and embedded in `beacon-otel`. The pinned upstream baseline remains Contrib `v0.65b0` (`a5470c666947acddc24fd4064ec7c1b169dfe8b6`) and Core `v1.44.0` (`53a5a40c9604583c501bcf13970a635f00e62df4`).

The 19 fix branches each passed their final CI checks. Their combined tree passed 221 Security tests, 110 Profiling tests and 12 package/base tests on CPython 3.12.3. Ruff lint, formatting, wheel/sdist builds and pinned metadata checks passed before release preparation.

A local HTTP/protobuf receiver validated OTLP Profiles empty, single-sample and multi-sample dictionaries with reserved zero entries and valid references. Lock, queue and logging workloads verified pre-allocation sampling, internal suppression, and finite buffer drops. These checks are protocol and workload validation, not a new DataKit backend qualification.

## Publication Gates

The final release candidate must pass installed-wheel CI on CPython 3.10–3.14, including the complete supported Security runtime suite on 3.11–3.14. The official tag workflow builds and tests the publication artifacts and publishes Profiling before the main package through protected GitHub environments.

Public PyPI installation, exact source and workflow links, artifact SHA-256 digests and post-publication acceptance will be recorded here after publication. This preparation record does not claim those steps have already completed.

## Boundaries and Rollback

See [release notes](../releases/1.2.1.md) for fixes and supported scope. Local traces, Logs and compatible pprof acceptance does not establish new production DataKit support. Profiling remains bounded and delivery is best effort. Security requires an application include prefix and supported standard-GIL CPython. Gunicorn requires `preload_app=False`.

Roll back in a clean environment using `beacon-otel[profiling,requests]==1.2.0`. Published artifacts and tags are immutable.
