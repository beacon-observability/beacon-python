# Beacon Python 0.1.0rc2 Acceptance Record

## Conclusion

`beacon-otel==0.1.0rc2` and `beacon-profiling==0.1.0rc2` passed acceptance.

- The public PyPI artifacts can be installed and used to start the FastAPI demo.
- When `OTEL_PROFILING_EXPORT_INTERVAL` is unset, profiles received by DataKit have a duration of 60 seconds.
- Profiles contain actual CPU Time, Wall Time, and Heap Live Size values.
- The compatible pprof output no longer includes `alloc-samples` or `alloc-space`, which it cannot represent correctly.
- Profiles do not include the `OTelProfileScheduler` collection thread.
- Demo requests, trace exports, and profile exports all succeeded.

## Known Limitations

- The current DataKit ingestion path uses compatible pprof rather than OTLP Profiles v1development.
- `tracemalloc` has noticeable overhead with many small objects and very short memory snapshot intervals. The default interval is 60 seconds and can be adjusted through an environment variable or constructor argument.
- After OpenTelemetry resource attributes enter DataKit, they are normalized according to the DataKit trace field model. Non-built-in tags may be retained in extended attributes.
