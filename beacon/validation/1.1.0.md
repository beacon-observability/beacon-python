# Beacon Python 1.1.0 Stable Release Acceptance Record

## Scope

`beacon-otel==1.1.0` embeds opt-in Beacon Security and runtime SBOM support in
the existing distribution. `beacon-profiling==1.1.0` is prepared under the same
product version. Security remains disabled by default and does not create local
diagnostic files unless explicitly enabled.

## Functional Baseline

- OpenTelemetry Python Contrib: `v0.65b0`
- OpenTelemetry Python Core: `v1.44.0`
- General Beacon runtime: CPython 3.10–3.14
- Beacon Security runtime: standard-GIL CPython 3.11–3.14
- Security contract: schema version 1 and fingerprint version 1
- Supported Security framework validation: Flask, Django, FastAPI/Starlette,
  Uvicorn, Gunicorn, requests, httpx, aiohttp, SQLAlchemy, sqlite3, psycopg, and
  PyMySQL boundaries covered by the release test suite

## Pre-release Validation

- The version, upstream baseline, Security provenance, schema fixtures, package
  metadata, entry points, and wheel contents are checked by
  `beacon/scripts/check-version.py`.
- CI builds both wheels and sdists and tests installed artifacts on CPython
  3.10–3.14.
- Schema conformance runs on every declared Python runtime; the complete
  Security runtime suite runs on CPython 3.11–3.14.
- Disabled-by-default lifecycle, enabled lifecycle, finding export, runtime
  SBOM, framework boundaries, Gunicorn post-fork setup, and clean
  uninstrumentation are covered by the release tests.
- Kubernetes usage uses the complete `beacon-otel` package in the application
  image and does not require a Security sidecar or init container.

The stable tag must be `v1.1.0` and must resolve to the exact merge commit that
passes all required checks.

## Post-release Acceptance

After publication, acceptance requires all of the following:

- PyPI exposes `beacon-otel==1.1.0` and `beacon-profiling==1.1.0`, each with a
  wheel and sdist.
- GitHub Release `v1.1.0` is stable, has the exact tag name as its title, and
  contains both packages' wheel and sdist artifacts.
- A clean environment installs the exact public `beacon-otel` version and
  reports `Beacon Python 1.1.0` from `beacon --version`.
- With Security configuration absent, startup creates no Security runtime or
  local files.
- With Security enabled for a real application module, the public package
  emits a finding and a runtime-SBOM event through OpenTelemetry Logs.

Post-release results are recorded only after these checks run against public
artifacts.

## Known Limitations

- Security source transformation requires an explicit application include
  selector for finding collection.
- Security supports standard-GIL CPython 3.11–3.14; CPython 3.10 receives
  schema and packaging validation only.
- Gunicorn must use `preload_app=False`; each worker initializes its own
  Security lifecycle.
- The current profiling ingestion path uses compatible `pprof` rather than the
  OpenTelemetry Profiles signal.
